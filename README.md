# Card Payment Analysis

카드 결제를 양면 시장(회원=수요 ↔ 가맹점=공급, 거래=매칭)으로 보고,
모니터링 → 드릴다운 → 예측으로 이어지는 분석 체계를 만듭니다.
카드사 사업기획·운영(이상거래) 관점의 인사이트 도출이 목표입니다.

## 데이터
- IBM 합성 신용카드 거래 24,386,900건 (1991~2020, Apache-2.0). **합성 데이터입니다.**
- MCC 업종명: greggles/mcc-codes (ISO 18245 기반).
- 분석 환경: BigQuery (GoogleSQL), 프로젝트 `card-payment-analysis`, 데이터셋 `card_raw`.

## 데이터 도메인
한 행은 결제 한 건이며, 합성 회원 2,000명의 카드 거래 로그입니다. 주요 컬럼과 의미는 다음과 같습니다.

| 컬럼 | 의미 | 도메인 메모 |
|---|---|---|
| `user_id` | 회원 ID | 합성 회원 2,000명 |
| `card_id` | 회원 내 카드 순번(0~8) | 고유 카드는 `(user_id, card_id)` 복합키 — 카드 수 집계 시 주의 |
| `amount` | 결제 금액 | **음수면 환불**. 원본 `"$134.09"` 문자열을 숫자로 변환 |
| `txn_datetime` | 거래 일시(분 단위) | 원본의 연·월·일·시:분을 합쳐 생성 |
| `use_chip` | 결제 채널 | `Chip`(IC 대면)·`Swipe`(마그네틱 대면)·`Online`(비대면) 3종 |
| `is_online` | 비대면 여부 | `use_chip = 'Online Transaction'` 파생 |
| `mcc` | 가맹점 업종 코드 | ISO 18245. `mcc_codes`로 업종명 매핑 |
| `merchant_name` | 가맹점 식별자 | 익명화된 정수 ID(STRING 유지) |
| `merchant_state` / `zip` | 가맹점 지역 | 약 11% 결측 — 온라인 거래로 추정 |
| `errors` | 거래 시 오류 메모 | 정상 거래는 비어 있음 |
| `is_fraud` | **부정(비인가) 거래 라벨** | 아래 설명 |

**`is_fraud`의 의미.** 카드 주인이 정상적으로 한 결제가 아니라, 도난·복제된 카드(번호)로 일어난 **비인가 거래**를 뜻합니다. 라벨은 가맹점이 아니라 **거래 한 건 한 건**에 붙습니다. 카드 대금 연체·상환 문제(delinquency)와는 무관합니다. 전체의 약 0.13%로 극도로 불균형하며, 비대면(`Online`) 채널에서 사기율이 대면보다 크게 높습니다 — 실물 없이 번호만으로 결제하는 card-not-present 도용 패턴과 일치합니다.

합성 데이터이므로 이 `is_fraud`도 실제 사고 기록이 아니라, IBM이 실제 도용 패턴을 흉내 내도록 규칙으로 생성해 넣은 라벨입니다.

### 결제 채널 (`use_chip`)
| 채널 | 비중 | 평균금액 | 사기율 |
|---|---|---|---|
| Swipe (마그네틱 대면) | 63.1% | $42.4 | 0.043% |
| Chip (IC 대면) | 25.8% | $41.1 | 0.077% |
| Online (비대면) | 11.1% | $56.7 | **0.676%** |

온라인은 건수 비중이 11%로 가장 작지만 사기율은 대면(Swipe) 대비 약 16배입니다. 위험이 비대면에 집중되어 이상거래 모니터링의 1순위 축이 됩니다.

### 금액
- 분위수: 중앙값 $30.1, p75 $65, p99 $316 — 소액 일상결제 중심입니다.
- 음수 금액(환불·취소)이 약 124만 건(5.1%), 0원 거래가 약 2만 건 있습니다. GMV·객단가 같은 지표를 정의할 때 환불 포함/제외 규칙을 명시합니다.

### 업종 (`mcc`)
- 데이터 내 업종 109개, 상위 20개가 전체 거래의 87.8%를 차지합니다. 공개표(greggles/mcc-codes)로 109개 전부 매핑됩니다.
- 거래량 상위는 식료품·주유·음식점 등 생활밀착 업종(사기율 0.01~0.07%로 낮음), 거래액 1위는 송금(4829)입니다.
- 사기율이 높은 업종은 백화점(0.54%)·할인점(0.47%)·도매클럽(0.20%) 등 대형 소매이며, 통행료·공과금은 사기율이 0입니다.

### 분석 윈도우 (2013~2019)
- 회원이 시간에 따라 생성되는 구조라(1991년 3명 → 2019년 1,579명), 초기 구간은 표본이 빈약합니다.
- 거래량·GMV는 2013년경 안정 수준(연 약 170만 건, GMV 약 $7,300만)에 도달합니다. 2020년은 2/28까지만 있는 부분 데이터입니다.
- 따라서 ramp-up 왜곡을 피해 **2013~2019 성숙 구간**을 분석 윈도우로 사용합니다.
- 합성 데이터라 월·요일 계절성은 거의 평탄하고(연말·명절·주말 구조 없음), 시간대 패턴만 뚜렷합니다(사기율은 한낮 10~13시에 최고). 시즌성 기반 시계열 이상탐지보다 구조적 드릴다운(업종·채널·시간)이 이 데이터에 정직한 접근입니다.

## 분석 체계
전체 흐름을 지표로 먼저 보고(모니터링), 이상이 잡히면 차원을 쪼개 원인을 좁히고(드릴다운),
그 신호를 모델로 점수화합니다(예측). 단발 EDA가 아니라 재사용 가능한 마트·뷰로 자산화하는 것이 목표입니다.

| 층위 | 산출물 | 위치 |
|---|---|---|
| 모니터링 | 월별·일별 KPI (거래량·사기율·온라인비중·환불) | `sql/analysis/01`, `sql/marts/daily_kpi` |
| 드릴다운 | 업종(MCC)·채널×시간대 사기 프로파일 | `sql/analysis/02`, `sql/analysis/03` |
| 예측 | 사기 이진분류 (BQML + sklearn) | `sql/ml/`, `python_scripts/` |

## 주요 결과
- **월별 모니터링 (EDA #1).** 거래량·평균 객단가는 평탄하고, 월별 사기율은 0~0.08% 범위에서 출렁입니다.
  합성 데이터라 뚜렷한 계절성은 없으며, 사기 라벨이 특정 월에 몰리는 형태입니다.
- **업종 드릴다운 (EDA #2).** 사기율 1위는 호텔 체인(윈덤/힐튼/메리어트 약 1.0~1.1%)과
  디지털 굿즈(0.78%) 등 **소액·비대면 업종**입니다. 사기율(rate)과 사기 건수 비중(share)을 분리해서 봐야
  "비율은 높지만 양은 적은" 업종과 "비율은 낮아도 양이 많은" 업종이 갈립니다.
- **채널×시간대 프로파일 (EDA #3).** **온라인 결제의 오전·오후 두 칸이 전체 사기의 약 54%**를 차지합니다
  (온라인×오전 27.9% + 온라인×오후 26.4%). 칩·스와이프 대면 채널은 같은 시간대라도 사기율이
  훨씬 낮습니다. 사기 프로파일을 종합하면 비대면 × 한낮 × 호텔/디지털/의류 업종으로 모입니다.
- **이상탐지 baseline (Track A).** 일별 사기율을 직전 30일 평균 대비 3σ(z-score) 기준으로 보면
  2013~2019 중 28일이 이상으로 잡힙니다. 며칠씩 뭉친 사기 급증 구간을 잘 잡아내는 한편,
  거래가 28건뿐이던 윤년(2016-02-29)의 사기율 14.3%가 오탐으로 잡혀 **최소 거래량 가드(≥1,000)**를
  추가했습니다 — 소표본 분모 아티팩트를 거르는 장치입니다.

## 구조
- `sql/staging/` — 적재·정제 파이프라인
- `sql/analysis/` — 분석 쿼리 (EDA·드릴다운)
- `sql/marts/` — 집계 마트 (`daily_kpi`)
- `sql/ml/` — 사기 예측 모델: 피처→학습→평가→threshold→비교 (BQML)
- `python_scripts/` — sklearn 재모델링·평가 (`fraud_model.py`)
- `results/tables/`, `results/figures/` — 결과 CSV·그래프

## BigQuery 객체 (card_raw)
- `transactions` — 분석용 타입 테이블 (2,438만)
- `transactions_staging` — STRING 원본 백업
- `mcc_codes` — MCC 업종명 참조표
- `transactions_labeled` — transactions + 업종명 뷰
- `daily_kpi` — 일별 KPI 마트 (모니터링 단일 소스)
- `daily_kpi_anomaly` — 이상탐지 뷰 (직전 30일 z-score + 이상 플래그)
- `fraud_features` — 사기 예측 피처/라벨 뷰 (time-split 포함)
- `fraud_lr` / `fraud_bt` — 사기 예측 모델 (로지스틱 회귀 / 부스팅 트리)
- `ml_sample` — Python 모델링용 균일 10% 샘플 (사기 비율 보존)

## 사기 예측 (Track B)
극불균형(사기 0.13%) 이진분류이며, 누수 방지를 위해 time-split(2013–17 train / 2018–19 test)을 적용했습니다.
- **BQML**: LR 베이스라인 ROC-AUC 0.66 → Boosted Tree 0.76 (log_loss 0.69→0.23).
- **Python(sklearn)**: HistGBT ROC-AUC 0.825, **PR-AUC 0.013** — 극불균형에서 ROC-AUC는 낙관적이라, PR-AUC/precision@K가 실질 성능을 보여줍니다. 위험순위 상위 0.1%만 검토해도 사기 농도가 base 대비 28.5배입니다.
- 피처 중요도: mcc(업종) > use_chip(채널) > amount > hour. `is_online`은 use_chip와 중복(다중공선성)입니다.
- 운영 함의: threshold 고정이 아니라 "알림 예산(top-K) 안에서 recall 극대화"로 접근합니다.
